### 3.2 ★ 一条任务书事实被 IL 证伪（**并连带更正了长期记忆**）

任务书 §2.2 与 §0.4.2 说：「去重键是相对文件夹根的路径，**所以** `<mod>\1.6\Defs\A.xml` 与 `<mod>\Defs\A.xml` 是两个不同的键、**会同时被加载**」。

**这是错的，且与它自身的前提矛盾。** 主理人自己写 IL 解码器反汇编 `Verse.DirectXmlLoader.XmlAssetsInModFolder`（527 字节）：

```
IL_0024 ldc.i4.0 → 按 list 顺序（降序=高优先级在前）遍历
IL_0091 get_FullName
IL_0096 ldloc.s 6 (= list[i])  → IL_0098 get_Length / IL_009D +1
IL_009F String::Substring      → key = FullName.Substring(list[i].Length + 1)
IL_00AB Dictionary::TryAdd     → 先到先得
```

两者相对**各自文件夹根**的路径**都是 `Defs\A.xml`** ⇒ **同一个键、只留一份**（`list[0]` 赢）。

**推论（本轮最值钱的一条）**：真正会同时进候选的是**相对键不同**的同名 def —— 那才是 `RD2026` 的来源；把「绝对路径不同」当成「都加载」会造出成批的**假 RD2026**。

> ⚠️ 这条错误此前已进入**长期记忆**（《引擎加载文件夹的权威语义》第 ④ 条），并从中复制进了 Task 3 任务书。关键记忆轨已由执行者建议更正并注入；**长期记忆轨的更正建议已另发**。

## 8. 方法论教训（本期累积，可直接复用）

1. **人工转写反编译文本只能当假设**：Task 1 转写被实测推翻 9 条；Task 3 任务书里的去重键结论同样是转写错误，靠 IL 证伪。
2. **每条转写都要配一条「能证伪它」的用例**，而不只是「能验证它」的。Task 2c 的两条证伪用例当场推翻了任务书。
3. **对着活跃写入中的语料做精确等值断言 = 假失败制造机**：正解是**把锚点落在不可变子集上**（`1668−42 = 1626`），而不是放宽成「基线 ± 容差」。
4. **零假阳门要分两层**：官方语料（证明不误报合法写法）＋ **会触发该规则形态的第三方语料**。只有前者时，规则能在生态上制造几万条噪音而门禁全绿。
5. **诊断的假阳比漏报更贵**：判据是「使用者会不会直接把报告关掉」。
6. **报数字前先问「这是我量的，还是我量的方式的产物」**：`[Unsaved]` 字段数存在**声明口径 427** 与**可见性口径 3,962** 两种，都对但不可混用。
7. **验收要显式贴出被断言项的计数**：主理人上轮只读了构建输出尾部，漏掉 1 条警告，导致「0 警告」的错误结论被记录了一轮。
8. **`[IO.File]` 用进程 CWD，不认 PowerShell 的 `cd`** —— 相对路径会静默读到别处。
9. **`edit` 的 3 字符锚点是位置相关的**：同一批 `edits` 里靠前的条目会移动靠后条目的锚点（`E_STALE_RANGE`）；**按行号从下往上改**，或拆成多次调用。
