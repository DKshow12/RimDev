## 5. 未覆盖项（诚实边界 · 六条）

每条写清「**没做什么 / 为什么 / 什么时候做**」，并尽量给出本期实测到的**规模**（而不是「大概」）。

1. **RD2017：自定义 Def 类型的字段校验被跳过。** 本期只加载原版 `Assembly-CSharp.dll`，**不加载 mod 程序集**，所以 `ThreatFleet.TF_MechModuleDef` 这类类型在 Managed 里找不到 → 字段名校验直接跳过，只报一条 info。**实测规模**：`check`（ThreatFleet）24 条 info、`check --all` 117 条 info，全部是这一类。**为什么**：加载第三方程序集需要独立的 `AssemblyLoadContext`（避免类型标识冲突与依赖解析失败），是独立工程量。**什么时候**：第 3 期（与「引用解析」同批，因为引用解析也必须先看得见 mod 类型）。

2. **`LoadOrderBuilder` 未实现 → 不判「同名 def 谁遮蔽谁」。** 索引只区分「启用 / 全部」，不建立 Core→DLC→activeMods 的严格加载顺序。**后果**：RD2004 只报「同一 `(DefType, defName)` 有多处声明」，**不报胜者是谁、哪份内容被静默丢弃**。**实测**：active 上只有 1 组真重名（`ThingSetMakerDef|MapGen_AncientComplexRoomLoot_Default`，Core + Ideology），且它是**原版自身的合法覆盖**——没有顺序模型就无法判断这一点，所以本期它的级别只能是 warning。**什么时候**：第 3 期。

3. **`--scope all` 有 17 个文件解析失败（真实工坊 XML 问题）。** **实测**：`filesFailed=17`（`xmlFiles=73024`），全部来自第三方工坊 mod 的真实坏 XML，**不是工具的缺陷**，不需要「修」。**能力缺口**：本期 `index --json` **只给计数、不给文件名**（`diagnostics: []`），所以这 17 个文件**目前无法定位**；RD2001 落地（带 `FileAbs` + `Line`）后才可枚举。**本次未做的事**：没有把这 17 个文件找出来逐个报告——那是 RD2001 的输出能力。**什么时候**：第 3 期随 RD2001 补全。

4. **`PatchOperation*` / `Inherit="False"` / `MayRequire` 过滤 / 引用解析 —— 均未做。** 本期是**纯静态**分析，不应用补丁、不做继承合并（`Inherit="False"` 的整块替换语义）、不按 `MayRequire` 跳过节点、不解析引用（`defaultProjectile` 之流）。**可观测后果**：`ParentName` 的口径只能是「**Name 空间优先 + defName 兜底**」的近似——这个兜底不是偷懒，而是对「补丁给 def 补 `Name` 属性」的有意近似（全库同形 61 条 / 11 个 mod，删掉兜底会凭空造 61 条假阳）。**什么时候**：第 3 期。

5. **`FieldNameCheck` 只校验顶层与一级子元素。** `<comps><li Class="...">` 这类**多态块的内层字段不校验**（需要按 `Class=` 分派到对应的 `CompProperties` 类型）。**为什么**：多态分派是独立工程量，浅做会大量误报（假阳比漏报更贵）。**实测**：本期 `check --all` 的 error 为 0，说明这条边界没有被掩盖的真问题——它只是**覆盖不到**，不是「查过了没问题」。

6. **`DefIndexStore` 的增量是「全量重扫 + 指纹统计」，不是真正的差量重扫。** 指纹只用来判定**是否需要重扫**（`Diff` 同时要求 `Changed.Count == 0 && Removed.Count == 0` 才走缓存快路径），一旦要扫就是**全量**。**实测证据**：`--rebuild` 时 `filesParsed=1649 / elapsedMs=506`；命中缓存时 `filesParsed=0 / filesSkippedByCache=1649 / elapsedMs=101`。**为什么**：真差量需要保留每文件的 def 列表并在合并时去重，复杂度高；当前语料规模下全量在**亚秒级**（全库 18.4 s）先保证正确。**什么时候**：第 3 期优化。

**另外两条「本期未启用」的退出码**（不算边界，但手册里要写清）：**1**（工具自身失败 / 未捕获异常）与 **6**（危险动作未加 `--yes`）**本期无任何触发路径**——CLI 对 `GameEnvProbeException` 都做了显式捕获并退 4，`--yes` 相关命令属第 5/6 期。实测确认的退出码只有 **0 / 2 / 3 / 4 / 5**。
