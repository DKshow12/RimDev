# RimDev 使用手册（v1）

> 本文对应第 1 期交付（`Docs\03-实施计划.md`）与**第 2 期**交付（`Docs\05-实施计划-第2期.md`；验收记录见 `Docs\06-第2期验收记录.md`）。工具位置：`<游戏根>\Mods\_rimdev\engine\`。

## 1. 这是什么

v1 覆盖三件事，**第 2 期再加两件**：

1. **环境探测** —— 一次拿到游戏根、Managed 目录、工坊目录、版本口径、日志位置
2. **成员查证** —— 「这个字段/类型到底存不存在」不用开游戏、不用等两分钟加载
3. **名字查证** —— 写错名字时给出最相近的候选（含大小写纠正）
4. **整份 XML 体检**（第 2 期）—— `check` 一次跑完五条规则：XML 良构 / 注释含 `--` / defName 重名 / ParentName 继承链 / 字段名，`--all` 对全部启用 mod；**官方内容上 0 error**
5. **Def 索引**（第 2 期）—— `index` 落盘 defs.jsonl + 指纹，active 全量约 0.5 s、全库约 18 s；`name check --kind def --index` 与 `check` 都读它

**核心主张**：本项目历史上因**凭语义猜原版名字**造成 8 次加载期错误，而「静态校验（XML 良构 + defName 去重）永远查不出来」——因为那些错误不是语法问题，而是名字在 1.6 里根本不存在。把 `Assembly-CSharp.dll` 反射进来，就能在命令行阶段把这类错误全部拦下。

## 2. 它解决的具体问题（都有历史案例）

| 你可能会写的 | 真实情况 | 工具怎么回答 |
|---|---|---|
| `canBeDeconstructed` | **不存在** | `api probe ThingDef --member canBeDeconstructed` → ✗、退出码 2 |
| `canBeDamagedByExplosions` | **不存在** | 同上 |
| `deconstructibleBlocks` | **不存在** | 同上 |
| 拆除该用什么 | `building/alwaysDeconstructible`、`resourcesFractionWhenDeconstructed` | `name check alwaysDeconstructible --owner BuildingProperties` → ✓ |
| `isMechanoid`（小写） | `IsMechanoid`（属性，大写 I） | `name check isMechanoid --kind property --owner RaceProperties` → ✗ + **大小写不符，正确写法是 IsMechanoid** |
| `Repair`（WorkTypeDef） | 1.6 只有 23 个 WorkTypeDef，**没有 Repair** | `name check Repair --kind def` → 明确告诉你「尚未实现，先用 rimsearcher」——**不猜**（Def 名查证属 v2） |

## 3. 命令

```powershell
$cli = '<游戏根>\Mods\_rimdev\engine\RimDev.Cli\bin\Debug\net8.0\rimdev.exe'

# ── 环境 ──────────────────────────────────────────────
& $cli env                  # 人类可读
& $cli env --json           # 结构化

# ── 成员查证（api）────────────────────────────────────
& $cli api probe <类型> [--member <成员名>]     # 单点查证，最常用
& $cli api type  <类型> [--filter <片段>]       # 列出成员（含非公开，带 * 标记）
& $cli api member <类型> --member <成员名>      # 同 probe
& $cli api ctor  <类型>                        # 构造器签名
& $cli api list  [--filter <片段>]              # 按名字片段找类型

# ── 名字查证（name）──────────────────────────────
& $cli name check <名字> [--kind type|field|property|method|enum|def] [--owner <类型>] [--json]
& $cli name check <defName> --kind def --index       # ★ 第 2 期：查落盘的 Def 索引

# ── 索引与体检（第 2 期新增）──────────────────────────
& $cli index [--scope active|all] [--rebuild] [--no-workshop] [--cache <目录>] [--json]
& $cli check [<mod>] [--all] [--severity error|warning|info] [--json]
```

### 3.1 三条必须知道的新行为（第 2 期）

1. **`--index` 读的就是 `rimdev index` 落的那个缓存。** 默认目录由 `DefIndexStore.DefaultCacheDir` **单点**决定（=`_rimdev\cache`），消费方不再各写一份。
   ★ 坑：`--scope all` 会**把该目录的作用域改写成 all**，而 `--index` 读的正是它——所以跑全库索引时**务必用 `--cache` 指到别处**：

   ```powershell
   & $cli index --scope all --cache '<游戏根>\Mods\_rimdev\cache-all'   # 全库索引，不碰 cache\
   & $cli index --scope active --rebuild                                # 万一用错了默认目录，用这条复原
   ```

2. **schema 不符报 `RD1004`，并把缓存「当作没有索引」——不静默作答。** 缓存 meta 的 schema 与当前版本不一致时，`--index` 会往 stderr 打：
   `RD1004: 索引缓存 schema=… 与当前 … 不符，先跑 \`rimdev index --rebuild\``，
   然后退回「未实现」分支（RD4006 Warning、**退出码 0**），**不会**拿旧缓存给你一个看起来正常的答案。

3. **`--severity` 只认 `error|warning|info`（不写 = `info`）。未知取值或缺值一律退 3**，不静默降级（静默降级属「静默错答」）。它只影响**报告条数**：

   ```text
   --severity error    → error 0   warning 0   info 0     exit=0
   --severity warning  → error 0   warning 1   info 0     exit=0
   --severity info     → error 0   warning 1   info 117   exit=0    （= 默认）
   --severity bogus    → exit=3
   ```

**`check` 的扫描口径**：无论是否指定 `<mod>`，**索引都是全集扫描**（本机实测 17 个 mod / 1649 个 XML / 14475 个 def），`<mod>` 只作**报告过滤器**；`--all` 去掉过滤器。省略 `<mod>` 时自动识别「工作区里含 `Source\*.csproj` 的 mod」（本机 = ThreatFleet），识别不到就报 RD1009 并退 5。

## 4. 退出码

| 码 | 含义 | 本期实测触发例 |
|---|---|---|
| 0 | 成功（无 Error 级结果）；「如实报未实现」的 Warning（RD4006）也是 0 | `rimdev index`；`rimdev check`（error 0）；`name check TF_ThreatHive --kind def --index`；`name check TF_ThreatHive --kind def`（无索引） |
| 1 | 工具自身失败（未捕获异常、I/O 错误） | **本期无触发路径**——环境异常都被显式捕获并退 4 |
| 2 | 执行成功，但存在 **Error** 级结果——这是「发现问题」，**不是**「工具坏了」（与 rimsearcher 的约定一致） | `name check TF_ThreatHiveX --kind def --index`（RD3001）；`name check isMechanoid --kind property --owner RaceProperties`（RD4005）；`check` 出现 error 时 |
| 3 | 参数错误 | 未知命令；**`--severity` 未知取值或缺值**（如 `--severity bogus`、`--severity` 后无值） |
| 4 | 环境不满足（RD1001 找不到游戏根 / RD5001 程序集载入失败） | 未实测触发（本机环境满足） |
| 5 | 目标 mod 找不到（RD1009） | `rimdev check no.such.mod` |

**用法提示**：在脚本里一律用退出码判断，不要去 grep 输出文本。

## 5. 三条必须知道的行为

1. **非公开字段也算存在。**
   `VerbProperties.forcedMissRadius` 是 **private** 字段，但它是合法的 XML 字段（本项目炮塔 Def 正在用）。
   工具会把它判定为**存在**并在证据里标 `isPublic False`；`api type` 输出里非公开成员前面有一个 `*`。
   > 如果按"只看 public 字段"实现，它会被误报成"不存在"——那比不做校验更糟。

2. **大小写敏感。**
   `IsMechanoid` 与 `isMechanoid` 是两次不同的查找；写错时错误码是 `RD4005`，提示里直接给出正确写法。

3. **命名空间不可假设。**
   `ThingDef` 在 `Verse`，而 `BuildingProperties` / `CompProperties_Refuelable` 在 `RimWorld`。工具一律按**简单名**全程序集查找，报告里给你全名。

## 6. 本期不做什么（诚实边界）

第 2 期**已完成、已从下表移出**：Def 名查证 `--kind def`（含 `--index`）、XML 良构 / defName 重名 / ParentName 继承链 / 字段名体检、Def 索引与指纹增量。

| 不做 | 原因 / 替代 |
|---|---|
| **引用悬空**（RD3001 的**真**引用解析：`defaultProjectile`、`soundCast` 之流） | 需要元数据知道每个字段是不是 Def 引用，属第 3 期。本期 `--kind def --index` 报的 RD3001 只是**查询语义**（这个名字在索引里不存在），不带引用点 |
| `PatchOperation*` 应用 / `Inherit="False"` 合并 / `MayRequire` 过滤 | 本期是**纯静态**分析，不做补丁与继承合并，属第 3 期。可观测后果：`ParentName` 用的是「Name 空间优先 + defName 兜底」的近似 |
| `LoadOrderBuilder`（同名 def 谁遮蔽谁） | 索引只区分「启用 / 全部」，不建 Core→DLC→activeMods 的严格顺序，属第 3 期 |
| 模拟加载（模拟游戏装载流程） | 属第 3 期起；现状见 `Docs\02-功能增补-基于实战经验.md` 的 F2–F14 |
| 反模式规则包（RD9001–RD9021） | 第 4 期 |
| 日志归因 / `--audit` / 语料回归 | 第 5 期 |
| 真机回归 `game run` | 第 6 期 |
| 执行 mod 代码（离线测试） | 第 7 期 |
| 多态块内层字段校验 | `FieldNameCheck` 只校验顶层与一级子元素；`<comps><li Class="…">` 内层需按 `Class=` 分派，属第 3 期 |
| 自定义 Def 类型的字段校验 | 只加载原版 `Assembly-CSharp.dll`，不加载 mod 程序集 → 报 RD2017（info）。第 3 期 |

## 7. 自测与重新构建

```powershell
& '<游戏根>\Mods\_rimdev\engine\build-all.ps1'
```

它会依次构建 `RimDev.Core` / `RimDev.Cli` / `RimDev.SelfTest`（每个都必须 `0 个警告 0 个错误`），然后运行自测台。退出码：`0` = 全部用例通过。

第 2 期后的自测规模：**75 个用例**（env 8 + metadata 13 + name 11 + catalog 11 + defscan 14 + check 13），全部断言值来自本机实测锚点，定义在 `RimDev.SelfTest\Facts.cs`。

> 游戏小版本更新后若自测失败，**先判断是否为版本漂移**（例如类型总数不再是 16157），而不是立刻怀疑代码。计划文档的 §0.2 列了全部锚点及其实测来源。

## 8. 项目位置与版本控制

```
<游戏根>\Mods\_rimdev\
├── engine\            .NET 8 源码（Core / Cli / SelfTest）+ build-all.ps1
├── Docs\              01 设计 / 02 功能增补 / 03 一期计划 / 04 本手册 / 05 二期计划 / 06 二期验收记录
├── logs\archive\      两份真实 Player.log（回归语料，不可再生）
├── cache\             索引落盘：defs.jsonl / fingerprints.json / index-meta.json（默认读这个，作用域 active）
├── cache-all\         全库索引专用（`index --scope all --cache` 指到这里，与 cache\ 分开）
├── reports\           （预留）
└── .git               本地仓库（无远程）
```

**注意**：本机 nuget.org 不可达、且沙箱禁止 `dotnet new`，因此
- 所有 `.csproj` 都是**手写**的，不要用 `dotnet new`；
- 项目**零外部 NuGet 依赖**（测试用自研断言台，不用 xunit）；
- **没有 `.sln`**，构建一律走 `build-all.ps1`。
