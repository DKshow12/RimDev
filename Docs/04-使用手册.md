> 本文对应**第 1 期**（`Docs\03-实施计划.md`）、**第 2 期**（`Docs\05-实施计划-第2期.md`，验收 `Docs\06-第2期验收记录.md`）与**第 3 期**（`Docs\07-实施计划-第3期.md`，验收 `Docs\08-第3期验收记录.md`；Task 7 的文档对齐与 V1–V8 实测见 `Docs\09`）。工具位置：`<游戏根>\Mods\_rimdev\engine\`。
>
> ★ **本文里的示例输出都是本机真跑过的**（2026-10-16，`1.6.4871`）；**凡标注「会漂移」的数字，都请以当场重跑为准**（`ThreatFleet` 正被另一写入者同时修改，启用集 XML 数、def 数、各行号都会变）。

## 1. 这是什么

v1 覆盖三件事，**第 2 期再加两件**，**第 3 期再加五件**：


1. **环境探测** —— 一次拿到游戏根、Managed 目录、工坊目录、版本口径、日志位置
2. **成员查证** —— 「这个字段/类型到底存不存在」不用开游戏、不用等两分钟加载
3. **名字查证** —— 写错名字时给出最相近的候选（含大小写纠正）
4. **整份 XML 体检**（第 2 期）—— `check` 一次跑完多条规则：XML 良构 / 注释含 `--` / defName 重名 / ParentName 继承链 / 字段名；`--scope active` 对全部启用 mod、`--scope all` 对全库
5. **Def 索引**（第 2 期）—— `index` 落盘 defs.jsonl + 指纹，active 全量约 0.5 s；`name check --kind def --index` 与 `check` 都读它
6. **文件发现口径对账**（第 3 期）—— `files`：按**引擎自己的 loadFolders 语义**算出每个 mod 实际加载哪些目录、去重后多少个 XML，并标出走的是哪个分支（`Origin`）
7. **加载顺序与遮蔽胜者**（第 3 期）—— `order`：Core → DLC → `activeMods` 的权威顺序 + 每个 mod 的文件夹优先级；`check --shadowing` 给出同名 def 的胜者/败者
8. **离线模拟加载**（第 3 期）—— `sim`：合并后的有效 def 集、遮蔽数、未解析父名、**悬空引用（RD3001）**、被 `MayRequire` 跳过数、自定义 loader 边界，每项可定位到 `文件:行`
9. **补丁与继承的静态求值**（第 3 期）—— `PatchOperation` 家族在合并后的 DOM 上求值（`RD2009`/`RD2014`）；`ParentName` 按引擎口径解析并带 `ResolutionBasis`
10. **全库体检**（第 3 期）—— `check --scope all`：3971 个 mod / 31 万 def（第 2 期只能体检启用的 17 个）

> 第 3 期的取舍边界（**不是缺陷，是有意为之**）见 §6。

**核心主张**：本项目历史上因**凭语义猜原版名字**造成 8 次加载期错误，而「静态校验（XML 良构 + defName 去重）永远查不出来」——因为那些错误不是语法问题，而是名字在 1.6 里根本不存在。把 `Assembly-CSharp.dll` 反射进来，就能在命令行阶段把这类错误全部拦下。

## 2. 它解决的具体问题（都有历史案例）

| 你可能会写的 | 真实情况 | 工具怎么回答 |
|---|---|---|
| `canBeDeconstructed` | **不存在** | `api probe ThingDef --member canBeDeconstructed` → ✗、退出码 2 |
| `canBeDamagedByExplosions` | **不存在** | 同上 |
| `deconstructibleBlocks` | **不存在** | 同上 |
| 拆除该用什么 | `building/alwaysDeconstructible`、`resourcesFractionWhenDeconstructed` | `name check alwaysDeconstructible --owner BuildingProperties` → ✓ |
| `isMechanoid`（小写） | `IsMechanoid`（属性，大写 I） | `name check isMechanoid --kind property --owner RaceProperties` → ✗ + **大小写不符，正确写法是 IsMechanoid** |
| `Repair`（WorkTypeDef） | 1.6 只有 23 个 WorkTypeDef，**没有 Repair** | `name check Repair --kind def` → 明确告诉你「尚未实现，先用 rimsearcher」——**不猜**（Def 名查证属 v2） |

## 3. 命令

```powershell
$cli = '<游戏根>\Mods\_rimdev\engine\RimDev.Cli\bin\Debug\net8.0\rimdev.exe'

# ── 环境 ──────────────────────────────────────────────
& $cli env                  # 人类可读
& $cli env --json           # 结构化

# ── 成员查证（api）────────────────────────────────────
& $cli api probe <类型> [--member <成员名>]     # 单点查证，最常用
& $cli api type  <类型> [--filter <片段>]       # 列出成员（含非公开，带 * 标记）
& $cli api member <类型> --member <成员名>      # 同 probe
& $cli api ctor  <类型>                        # 构造器签名
& $cli api list  [--filter <片段>]              # 按名字片段找类型

# ── 名字查证（name）──────────────────────────────
& $cli name check <名字> [--kind type|field|property|method|enum|def] [--owner <类型>] [--json]
& $cli name check <defName> --kind def --index       # ★ 第 2 期：查落盘的 Def 索引

# ── 索引与体检（第 2 期）──────────────────────────────
& $cli index [--scope active|all] [--rebuild] [--no-workshop] [--cache <目录>] [--json]
& $cli check [<mod>] [--scope target|active|all] [--all] [--only-official] [--shadowing] [--severity error|warning|info] [--json]

# ── 文件发现 / 加载顺序 / 离线模拟（第 3 期新增）──────────
& $cli files [--scope active|all] [--explain <mod>|all] [--filter <片段>] [--limit <N>] [--json]
& $cli order [--explain] [--json]
& $cli sim   [<mod>] [--scope target|active|all] [--all] [--json]
```

### 3.1 三条必须知道的新行为（第 2 期）

1. **`--index` 读的就是 `rimdev index` 落的那个缓存。** 默认目录由 `DefIndexStore.DefaultCacheDir` **单点**决定（=`_rimdev\cache`），消费方不再各写一份。
   ★ 坑：`--scope all` 会**把该目录的作用域改写成 all**，而 `--index` 读的正是它——所以跑全库索引时**务必用 `--cache` 指到别处**：

   ```powershell
   & $cli index --scope all --cache '<游戏根>\Mods\_rimdev\cache-all'   # 全库索引，不碰 cache\
   & $cli index --scope active --rebuild                                # 万一用错了默认目录，用这条复原
   ```

2. **schema 不符报 `RD1004`，并把缓存「当作没有索引」——不静默作答。** 缓存 meta 的 schema 与当前版本不一致时，`--index` 会往 stderr 打：
   `RD1004: 索引缓存 schema=… 与当前 … 不符，先跑 \`rimdev index --rebuild\``，
   然后退回「未实现」分支（RD4006 Warning、**退出码 0**），**不会**拿旧缓存给你一个看起来正常的答案。

3. **`--severity` 只认 `error|warning|info`（不写 = `info`）。未知取值或缺值一律退 3**，不静默降级（静默降级属「静默错答」）。它只影响**报告条数**：

   ```text
   --severity error    → error 0   warning 0   info 0     exit=0
   --severity warning  → error 0   warning 1   info 0     exit=0
   --severity info     → error 0   warning 1   info 117   exit=0    （= 默认）
   --severity bogus    → exit=3
   ```

**`check` 的扫描口径**：无论是否指定 `<mod>`，**索引都是全集扫描**（本机 2026-10-16 实测 **17 个 mod / 1688 个 XML / 14801 个 def**；这个数**会漂移**，历史值曾是 1649 / 14475），`<mod>` 只作**报告过滤器**。省略 `<mod>` 时自动识别「工作区里含 `Source\*.csproj` 的 mod」（本机 = ThreatFleet），识别不到就报 RD1009 并退 5。

★ **`--all` 在 `check` 与 `sim` 里的语义** **不同**，这是最容易踩的一个坑：

| 命令 | `--all` 的含义 | 想表达「全库」要写 |
|---|---|---|
| `check` | **兼容别名 = `--scope active`**（第 2 期的旧写法继续可用） | `check --scope all` |
| `sim` | **= 全库**（`--scope all`） | `sim --all` 或 `sim --scope all` |

（`files --scope` 只有 `active|all` 两个取值，没有 `target`。）

### 3.2 `rimdev files` —— 引擎口径的文件发现对账（第 3 期新增）

**它回答**：「这个 mod 到底加载了哪些目录、去重后有多少个 XML、走的是引擎哪一条分支？」—— 这是第 2 期 `files=1649` 与独立枚举对不上 193 的根因所在（详见 `07` §0.4.0）。

```text
$ rimdev files --scope active
scope            active
引擎版本口径      1.6.4871（CurrentVersionStringWithoutBuild=1.6，来源=reflection）
mod 数           17   （目录表 3971 / 启用 17）
XML 文件总数     1688   （按引擎口径去重后）

brrainz.harmony  (2009463077)
   Origin=LowerVersion  MatchedVersionKey=1.6  Folders=2  XmlFileCount=0  Issues=0
   [0]   …\294100\2009463077\1.6
   [1]   …\294100\2009463077
dsh.threatfleet.fragments  (ThreatFleet)
   Origin=LowerVersion  MatchedVersionKey=1.6  Folders=2  XmlFileCount=62  Issues=0
   [0]   …\Mods\ThreatFleet\1.6
   [1]   …\Mods\ThreatFleet
sakurakoujiruna.dronetest.funnels  (3810712257)
   Origin=LowerVersion  MatchedVersionKey=1.6  Folders=3  XmlFileCount=49  Issues=0
   [0]   …\1.6   [1]   …\Common   [2]   …<root>
```

（上面只摘了 3 个 mod；完整 17 行见 `09`。）

**怎么读这几列**：
- **`Origin`** = 引擎实际走的分支：`ExactVersion` / `LowerVersion`（向下取版本，**绝大多数 mod 走这条**）/ `Default` / `FallbackDir`（没有 `loadFolders.xml`）/ `Empty`（**解析出的目录列表为空 ⇒ 该 mod 的 def 根本不会被加载**）。
- **`[0]` 是优先级最高**：`[0]` 会遮蔽 `[1]` 里的同名相对路径文件。
- **`XmlFileCount` 是「该 mod 按引擎口径去重后」的 XML 数**（`Defs` + `Patches`），不是磁盘上的 `*.xml` 总数。
- **`Issues`** 是 loadFolders 规则族（`RD2012` / `RD2018–RD2024`）的命中数。

**全库一行值（`--json`）**：`modsScanned=3971` / `xmlFileCount=59110` / `byOrigin = { FallbackDir: 2484, LowerVersion: 1467, Empty: 20 }` / `issues` 共 151 条、分布 36 个 mod。

**`--explain <mod>`** 只缩小**打印粒度**，不改范围判定：

```text
$ rimdev files --scope active --explain ThreatFleet
mod 数           1   （目录表 3971 / 启用 17）
XML 文件总数     1688   （按引擎口径去重后）     ← ★ 注意：这一行仍是【整个 scope】的总数，不是该 mod 的

dsh.threatfleet.fragments  (ThreatFleet)
   Origin=LowerVersion  MatchedVersionKey=1.6  Folders=2  XmlFileCount=62  Issues=0
```

**稳。定。不。变。量（可精确断言）**：`files --scope active --json` 的 `xmlFileCount` **减去 ThreatFleet 自己的 `xmlFileCount`** = **1626**（`1688 − 62 = 1626`）。ThreatFleet 由另一位写入者同时修改，所以只有「减掉它」的子集不可变；这个不变量在本期已连过 9 次快照（`1649−23` … `1688−62`）。

⚠️ **已知显示不一致（未修）**：`files --explain <mod>` 的 `mod 数` 已经是过滤后的 1，但 `XML 文件总数` 仍打印**整个 scope** 的总数（1688）—— 看到「1 个 mod / 1688 个 XML」别以为工具算错了。

## 4. 退出码

## 5. 必须知道的行为

1. **非公开字段也算存在。**
   `VerbProperties.forcedMissRadius` 是 **private** 字段，但它是合法的 XML 字段（本项目炮塔 Def 正在用）。
   工具会把它判定为**存在**并在证据里标 `isPublic False`；`api type` 输出里非公开成员前面有一个 `*`。
   > 如果按"只看 public 字段"实现，它会被误报成"不存在"——那比不做校验更糟。

2. **大小写敏感。**
   `IsMechanoid` 与 `isMechanoid` 是两次不同的查找；写错时错误码是 `RD4005`，提示里直接给出正确写法。

3. **命名空间不可假设。**
   `ThingDef` 在 `Verse`，而 `BuildingProperties` / `CompProperties_Refuelable` 在 `RimWorld`。工具一律按**简单名**全程序集查找，报告里给你全名。

4. **引用只以「元素文本」或 `<li>` 形态出现 —— 属性形态不是引用载体**（第 3 期 IL 实证）。
   写 `<soundCast>Shot_MachineGun</soundCast>` 会被 `RD3001` 抓住；写 `soundCast="Shot_MachineGun"`（属性）**永远不会被检查** —— 因为引擎的 XML 加载器从不按属性名读引用字段：`XmlElement.GetAttribute(string)` 在 `DirectXmlToObject`/`XmlToObjectUtils`/`XmlInheritance`/`DirectXmlLoader` 里调用 **0 次**；官方 6 包 3,234 份 XML 里 `soundCast="` 等 6 个属性名**全部 0 命中**。§3.5 与 `01` §7 的 RD3001 行记了完整证据。

5. **`--all` 在 `check` 与 `sim` 里含义不同**（第 3 期）：`check --all` = `--scope active` 的**兼容别名**；`sim --all` = **全库**。想在全库上跑体检要写 `check --scope all`。见 §3 上方那张表。

6. **默认缓存目录是单点的**（第 2 期）：`DefIndexStore.DefaultCacheDir` = `_rimdev\cache`；`index --scope all` 会**把该目录的作用域改写成 all**，所以全库索引务必加 `--cache <另一个目录>`（见 §3.1 的坑）。

## 6. 本期不做什么（诚实边界）

**已完成、已从下表移出**：

- **第 2 期**：Def 名查证 `--kind def`（含 `--index`）、XML 良构 / defName 重名 / ParentName 继承链 / 字段名体检、Def 索引与指纹增量。
- **第 3 期**：`files`（引擎口径的文件发现）、`order`（加载顺序 + 文件夹优先级）、遮蔽胜者与「同 mod 内重名」（`RD2025` / `RD2026`）、`PatchOperation` 系列静态求值（`RD2009` / `RD2014`）、`ParentName` 的引擎等价解析 + `Inherit="False"` 合并、**引用悬空 `RD3001`（真引用解析，带引用处 `文件:行`）**、`MayRequire` 跳过建模（`RD2008`）、`check --scope all`（全库 3971 mod / 31 万 def）、`sim`（离线模拟加载）。

| 不做 | 原因 / 替代（2026-10-16 复核） |
|---|---|
| **`sim --scope all` 的性能** | **当前 807 s，未达 `01` §9.2 的 ≤ 30 s**（`--scope active` 约 2.6 s，达标）。瓶颈已定位在**引用解析自身（占 87%）**。作者已立项 **Task 8「压实现」**：**目标值不改、测量范围不缩，动的是实现**。⇒ **不要**把 `--scope active` 的达标当成全量达标 |

## 7. 自测与重新构建

```powershell
& '<游戏根>\Mods\_rimdev\engine\build-all.ps1'
```

它会依次构建 `RimDev.Core` / `RimDev.Cli` / `RimDev.SelfTest`（每个都必须 `0 个警告 0 个错误`），然后运行自测台。退出码：`0` = 全部用例通过。

**自测规模随期数增长**：第 2 期交付时 **75 个用例**（env 8 + metadata 13 + name 11 + catalog 11 + defscan 14 + check 13）；第 3 期 Task 5c 时 **239/239/0**，Task 6b 收尾时 **265/265/0**（用例定义在 `RimDev.SelfTest\Facts.cs` 与 `Cases\Phase3Task*Cases.cs`）。
★ **本节不写死具体数字** —— 自测计数**会随 Task 滚动**（Task 8 正在改 `engine`），且本手册不负责验收；**以 `build-all.ps1` 当场输出的「合计 N 个用例：M 通过」为准**，历史快照在 `Docs\06` / `Docs\08`。

> 游戏小版本更新后若自测失败，**先判断是否为版本漂移**（例如类型总数不再是 16157），而不是立刻怀疑代码。计划文档的 §0.2 列了全部锚点及其实测来源。
