**Goal:** 把第 2 期建好的索引从「能扫出 def 头」推进到「**能复现引擎的加载结果**」：加载文件夹解析与游戏逐行等价，加载顺序与遮蔽胜者可判定，补丁与继承按引擎时序静态求值，引用悬空能定位到 `文件:行`。产出三条实用命令——`rimdev files`（文件发现口径对账）、`rimdev order`（加载顺序 + 遮蔽胜者）、`rimdev sim`（离线模拟加载）。

**Architecture:** `RimDev.Core` 的 `Catalog` 层扩展为**三层**：`ModCatalog`（目录表，第 2 期）→ `LoadFolderResolver`（引擎等价的文件夹解析，本期新增）→ `LoadOrderBuilder`（顺序 + 遮蔽胜者，本期新增）。`Defs` 层在第 2 期 `DefScanner`/`DefIndex` 之上加 `PatchLayer`（补丁求值）与 `InheritanceLayer`（继承合并），产出 `EffectiveDef`。`Checks` 层新增 `LoadFolderCheck`（规则族 RD2012/RD2018–RD2024）与 `ReferenceCheck`（RD3001）。**零外部 NuGet 依赖不变。**

**Tech Stack:** 沿用第 1/2 期：C# 12 / .NET 8 / 手写 csproj / 自研断言台 `Harness.cs` / `System.Text.Json` / `System.Xml.XmlReader` + `XmlDocument`（XPath 1.0 补丁求值需要 DOM）。

### 0.4 引擎权威语义（反编译逐行，本期**唯一**口径）

> 以下四段是 2026-10-14 从 `Assembly-CSharp.dll`（mvid `61e4173561894da49d210260257b5097`）反编译得到的**原文**，是本次体检最重要的产出：它同时解释了 F2/F7，并且是 Task 1/3 的实现依据。**实现时以本节为准，不以第 2 期的 `LoadFoldersReader` 为准。**

#### 0.4.1 `Verse.ModContentPack.InitLoadFolders()`（私有，`ReloadContentInt` 调用）

```csharp
foldersToLoadDescendingOrder = new List<string>();
var m = ModLister.GetModWithIdentifier(PackageId);
if (m?.loadFolders != null && m.loadFolders.DefinedVersions().Count > 0)
{
    var a = m.LoadFoldersForVersion(VersionControl.CurrentVersionString);   // 精确匹配当前版本串
    if (a != null && a.Count > 0) { AddFolders(a); return; }

    var best = (from x in m.loadFolders.DefinedVersions()
                where x != "default" && !x.NullOrEmpty() && x.Contains(".")
                   && VersionFromString(x) <= VersionControl.CurrentVersion   // ★ 向下取版本
                orderby x descending select x).FirstOrDefault();
    if (best != null) {
        var b = m.LoadFoldersForVersion(best);
        if (b != null) { AddFolders(b); return; }
    }
    var c = m.LoadFoldersForVersion("default");                               // ★ default 键兜底
    if (c != null) { AddFolders(c); return; }
}
if (foldersToLoadDescendingOrder.Count != 0) return;

// ── 回退分支（没有 loadFolders，或 loadFolders 一个可用版本都没有）──
string dir = Path.Combine(RootDir, VersionControl.CurrentVersionStringWithoutBuild);  // <mod>\1.6
if (Directory.Exists(dir)) foldersToLoadDescendingOrder.Add(dir);
else {
    // 取 mod 根下名字能解析成版本号的最大者（不在当前版本之后者优先），只取一个
    ... version = max(versions); 
    if (version.Major > 0) foldersToLoadDescendingOrder.Add(Path.Combine(RootDir, version.ToString()));
}
string common = Path.Combine(RootDir, CommonFolderName);       // "Common"
if (Directory.Exists(common)) foldersToLoadDescendingOrder.Add(common);
foldersToLoadDescendingOrder.Add(RootDir);                     // ★ 永远最后加根目录

void AddFolders(List<LoadFolder> folders) {
    for (int i = folders.Count - 1; i >= 0; i--)               // ★★ 倒序遍历
        if (folders[i].ShouldLoad)
            foldersToLoadDescendingOrder.Add(Path.Combine(RootDir, folders[i].folderName));
}
```

**四条必须记住的语义（都与第 2 期的实现不同）**：
1. **`loadFolders.xml` 存在时，根目录默认【不加载】**。只有走「回退分支」才会加根目录。第 2 期把「无 1.6 键」当成回退 → 与引擎不一致（**这就是 F2 的 193 差**）。
2. **无 1.6 键时不是回退，而是「向下取版本」**（`1.5` / `1.4` … 取 ≤ 当前版本的最大者）；再不行才取 `default` 键；三者都没有才回退到根目录逻辑。
3. **`Common` 只在回退分支被加入**（有 `loadFolders` 的 mod 想要 `Common` 必须自己在 `<li>` 里写）。
4. **`foldersToLoadDescendingOrder[0]` 优先级最高**，而 `AddFolders` 是**倒序**追加 —— 所以 **`<li>` 列表中越靠后的条目优先级越高**（与直觉相反，必须实测确认，见 Task 1 Step 6）。

#### 0.4.2 文件夹优先级与去重（`DirectXmlLoader.XmlAssetsInModFolder`）

```csharp
List<string> list = foldersToLoadDebug ?? mod.foldersToLoadDescendingOrder;
var dict = new Dictionary<string, FileInfo>();
for (int i = 0; i < list.Count; i++) {
    var di = new DirectoryInfo(Path.Combine(list[i], folderPath));   // folderPath = "Defs" / "Patches"
    if (!di.Exists) continue;
    foreach (var f in di.GetFiles("*.xml", SearchOption.AllDirectories))
        if (!f.Name.StartsWith("._") && !f.Name.StartsWith("."))     // ★ 跳过点文件
            dict.TryAdd(f.FullName.Substring(list[i].Length + 1), f); // ★ 键 = 相对该文件夹根的路径
}
```

**两条关键结论**：
- 去重是 **`TryAdd` 先到先得** ⇒ **`list[0]` 赢** ⇒ 越靠后声明的 `<li>` 赢（与 §0.4.1 一致）。
- 去重键是**相对文件夹根**的路径 ⇒ `<mod>\1.6\Defs\A.xml` 与 `<mod>\Defs\A.xml` 是**两个不同的键，会同时被加载**（回退分支下根 + `1.6` 同时生效，同名 def 于是产生「同 mod 内重名」）。
- `<li>/</li>`（或 `\`）经 `LoadDataFromXmlCustom` 存成 `folderName = ""`，`Path.Combine(RootDir, "")` == `RootDir`（**须在 Task 1 里用一条自测钉住**，别凭记忆）。

`Verse.ModContentPack.GetAllFilesForModPreserveOrder`（另一条消费者，用于 `Patches` 之外的资源枚举）：**倒序**遍历文件夹后**再从尾部向前去重**，胜者同样是 `list[0]`，但**返回顺序是「低优先级在前」**——如果将来要复刻补丁应用顺序，这个差异必须单独处理。

#### 0.4.3 `loadFolders.xml` 的解析（`Verse.ModLoadFolders.LoadDataFromXmlCustom`）

```csharp
foreach (XmlNode child in xmlRoot.ChildNodes) {            // 版本块，如 <v1.6> / <1.6> / <default>
    if (child is XmlComment) continue;
    string key = child.Name.ToLower();
    if (key.StartsWith("v")) key = key.Substring(1);       // ★ v1.6 与 1.6 归一到 "1.6"
    ...
    foreach (XmlNode li in child.ChildNodes) {
        if (li is XmlComment) continue;
        var any = li.Attributes?["IfModActive"]?.Value.Split(',').Select(s => s.Trim()).ToList();
        var all = li.Attributes?["IfModActiveAll"]?.Value.Split(',').Select(s => s.Trim()).ToList();
        var not = li.Attributes?["IfModNotActive"]?.Value.Split(',').Select(s => s.Trim()).ToList();
        if (li.InnerText == "/" || li.InnerText == "\\") { add(new LoadFolder("", any, all, not)); continue; }
        string name = li.InnerText.Replace(Path.AltDirectorySeparatorChar, Path.DirectorySeparatorChar);
        add(new LoadFolder(name, any, all, not));
    }
}
```

**结论**：`ShouldLoad` = `any`（任一启用）/ `all`（全部启用）/ `not`（任一都不启用）三个条件的合取，判定依据是**当前启用集合的 packageId**。
`ModLoadFolders.FoldersForVersion(v)` = `foldersForVersion.TryGetValue(v)`，**无命中返回 null，类内部不做任何回退**。

> ★ **待实测（Task 1 Step 3 必须打印）**：`VersionControl.CurrentVersionString` 到底是 `"1.6"` 还是 `"1.6.4871"`，决定了 §0.4.1 走的是**精确分支**还是**向下取版本分支**。两者对 `<v1.6>` 的结果相同，但对「同时定义了多个版本键」的 mod 不同。**不要在实现里猜**：把实际走的分支记进 `LoadFolderResolution.Origin`（`ExactVersion | LowerVersion | Default | FallbackDir`）并在 `rimdev files --explain <mod>` 里打印。

#### 0.4.4 引擎自带的 loadFolders 校验清单（= 我们的规则族定义）

`Verse.ModLoadFolders` 自带 `GetIssueList`，给出的 issue 名就是权威规则表：

| 引擎 issue 名 | 含义 | 我们的码（见 §0.5） |
|---|---|---|
| `ModLoadFolderListEmpty` | 版本块里一个 `<li>` 都没有 | RD2018 |
| `ModLoadFolderRepeatingFolder` | **同一个版本块内 `<li>` 重复** | RD2019 |
| `ModLoadFolderMalformedVersion` | 版本键格式非法（不 `Contains(".")` 等） | RD2020 |
| `ModLoadFolderDefaultDeprecated` | 用了 `default` 键（已废弃） | RD2021 |
| `ModLoadFolderOutOfOrder` | 版本键**未升序** | RD2022 |
| `ModLoadFolderDoesntExist` | `<li>` 指向的目录不存在 | **RD2012（已有）** |
| `ModLoadFolderDefinesUnsupportedGameVersion` | 声明的版本 > 当前游戏版本 | RD2023 |

> 注：这两条规则的**级别必须分开定，不许一律 error**。`ModLoadFolderRepeatingFolder`（同一块内 `<li>` 重复）**不影响**加载结果（`AddFolders` 产生的重复路径会在文件枚举阶段被 `TryAdd` 去重），故 warning；而 `ModLoadFolderOutOfOrder`（版本键未升序）**可能真的影响结果** —— `orderby x descending` 是**字符串序**，`"1.9" > "1.10"`，见 Task 1 Step 7 的反例用例，级别待该用例的实测结论定。

#### 0.4.5 第 2 期实现 vs 引擎：差异对照表（F2/F7 的根因）

| 情形 | 第 2 期 `LoadFoldersReader` 的做法 | 引擎的做法 | 后果 |
|---|---|---|---|
| mod 有 `loadFolders.xml` 且有 1.6 键 | 用 1.6 块的 `<li>` | 同（精确或向下取版本） | 一致 |
| mod 有 `loadFolders.xml` **无 1.6 键**（实测 **48 个**） | 回退到 `根 + <mod>\1.6` | **向下取版本**（如 `1.5`）/ `default`；**不含根、不含 1.6** | ❌ 口径不一致 → **F2 的 193** |
| mod **无** `loadFolders.xml`（启用集里 12/17 属此类） | `根 + <mod>\1.6` | `根 + <mod>\1.6 + Common`（存在才加） | ⚠️ 少了 `Common` |
| `<li>` 顺序 | 按 XML 顺序 | **倒序**（越靠后越优先） | ⚠️ 遮蔽胜者可能相反 |
| `<li IfModActive="x">` | 忽略属性（照加载） | 条件不满足则**不加载** | ❌ 多算 |
| `<li>/</li>` | 未处理 | mod 根 | ❌ 漏算 |
| 点文件（`.` / `._` 开头） | 未排除 | 排除 | ⚠️ 多算 |

> **193 的定位方向**：48 个「有 loadFolders 但无 1.6 键」的 mod，如果它们的 def 放在 `1.5\Defs\` 之类的**低版本目录**里，第 2 期会去看 `根\Defs` 与 `1.6\Defs` → **漏掉**这些文件。这正好是「我们比独立探针**少** 193」的方向。
> **但这是推断，不是结论**：Task 2 Step 5 必须给出**逐 mod 的 delta 明细表**，逐个解释，不许用「大概是这个原因」结案。

5. **真机回归（`game run`）不在本期**：日志归因引擎与 baseline 差分留给第 4/5 期。
